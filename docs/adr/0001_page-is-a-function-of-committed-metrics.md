# The published page is a function of the committed metrics

Date: 2026-08-18
Status: accepted
Author: Piotr Cząstkiewicz
Related to: [0002_challenge-set-design.md](0002_challenge-set-design.md)

---

## Context

The first version of the report was a Python f-string that embedded a base64 matplotlib PNG
and stamped `date.today()` into the footer. Three consequences followed from that, and only
the first was cosmetic:

1. The chart carried a white background into a dark page, so the figure was the one element
   nobody could style.
2. Nothing connected the published HTML to the numbers it claimed to show. A hand-edit to
   `docs/index.html` — a corrected typo, a "temporarily" adjusted figure — would survive
   indefinitely, because rebuilding was optional and nothing compared the two.
3. The build was not reproducible: two builds of the same metrics differed in the footer, so
   no automated check could exist even if someone wanted one.

The comparison project `it-job-radar` had already solved the same problem, and the two sites
are read as one body of work.

## Decision

The page is generated by `pl_review_sense.site` from `reports/metrics/` and nothing else.

- **Jinja2 template + shared stylesheet.** The palette, type scale and component vocabulary
  are the ones `it-job-radar` uses, as CSS variables with a dark scheme that swaps the
  variables rather than restating the design.
- **Figures are inline SVG**, generated by pure functions from numbers to markup. They inherit
  the reader's colour scheme, stay sharp, and their text is real text.
- **No wall clock, no dataset, no model.** The footer timestamp is the one the analysis
  recorded in `manifest.json`, alongside the git sha the numbers were produced at.
- **CI rebuilds the page and diffs it** against the committed `docs/index.html`. A mismatch
  fails the build with the command that fixes it.
- **A figure without its counts is not publishable**: the build raises `IncompleteFigure`
  rather than shipping marks whose sample size is not stated.
- **Panels render in every state.** Evidence that has not been produced yet — the paired
  comparison with HerBERT, the cascade — renders as a panel saying what is missing and how it
  would be settled. A section that disappears until its data arrives looks like a page that
  never had one.

## Consequences

- `python -m pl_review_sense.report` is gone; the entry point is `python -m pl_review_sense.site`.
- `jinja2` and `scipy` become direct dependencies. Both were already installed transitively;
  the project now imports them directly and says so.
- Analysis and publication are separate steps. `analysis` writes one JSON per question the
  page asks, so a measurement that has not been run leaves its own panel waiting rather than
  blocking the build.
- The page can no longer be edited into saying something the numbers do not — which is the
  point, and also means every copy change now lives in the template.

## Alternatives considered

**Keep the f-string, restyle the CSS only.** Cheapest, and it would have fixed the palette.
It fixes neither the PNG in dark mode nor the absence of any link between the page and the
metrics, and the drift check — the thing that makes the page trustworthy rather than
merely tidy — is impossible without a reproducible build.

**Publish through a static-site generator.** More machinery than one page needs, and it would
put the layout a step further from the code that computes the numbers.
