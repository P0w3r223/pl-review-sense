# 2026-08-18 — evidence, and a page that cannot drift from it

Branch `feat/evidence-and-site-parity`, PR [#4](https://github.com/P0w3r223/pl-review-sense/pull/4)
(merged). Follow-up branch `feat/page-depth`, PR
[#5](https://github.com/P0w3r223/pl-review-sense/pull/5) (open, CI green).

Extended the project along the axis its own thesis needed and rebuilt the published page in
the `it-job-radar` visual system so the two portfolio sites read as one body of work. Five new
pure modules (`stats`, `curves`, `challenge` + `challenge_set`, `cascade`, `interpret`), an
`analysis` runner that is now the only writer of `reports/metrics/`, and a `site/` package
(Jinja template, shared `styles.css` with first-class dark mode, inline-SVG charts) replacing
the f-string `report.py`. CI gained a drift job that rebuilds the page and fails if
`docs/index.html` disagrees with the committed metrics; it passes on Linux, so the LF handling
and `.gitattributes` are right.

The finding worth remembering: the baseline scores 0.944 macro-F1 on PolEmo and answers only
48 of 80 one-sentence probe reviews (13/20 on the *control* cell), while its heaviest neutral
coefficients are topical rather than evaluative — the class is partly being recognised by
subject matter. Those two facts explain each other, and the page's headline is derived from
them, so it changes if they stop being true.

**Review round** (same branch, three further commits). A code review and a test review found
five real defects between them, two of which contradicted the branch's own stated principles: a
figure with nothing to draw crashed the build instead of rendering the "no evidence yet" panel
written for it, and the derived headline would have announced a significantly *worse* HerBERT as
a win. Also fixed: `stratified_indices` returning more rows than asked for, `cascade` dividing by
zero where its twin returned `[]`, and `baseline.save`/`load` binding the model path as a default
argument at import — which let a test overwrite the trained model (restored, 3 236 052 bytes).
The suite went 97 → 179 tests, the important addition being a round trip that runs the real
writers and renders the page from what they wrote: the fixture-based site tests could not catch a
key renamed in `analysis`. `CLAUDE.md` was tightened against the agent-engineering guidance —
each rule now states why it exists, the thrice-repeated I/O rule says itself once, and a rule
quoting "684 test rows" no longer carries a fact that can go stale.

**Page-depth round** (`feat/page-depth`, PR #5, 202 tests). Added reference floors — always the
majority class scores 0.221 macro-F1 at 0.496 accuracy, which is the argument for the headline
metric stated as a measurement — the direction of the probe's misses (8 of the sarcasm misses are
negatives read as positive, so the model takes ironic praise literally), and a section that cuts
the test predictions by review length to put the page's own headline at risk.

That last one is the thing to remember, because it went the other way. The first run produced
`trend = +0.33`, a spectacular confirmation of the claim — and an artefact: the 25–49-word bucket
yields 90% accuracy and 0.62 macro-F1 from the same thirty rows, because one class contributed a
handful of them. Raising the segment floor to 50 and averaging macro-F1 over only the classes
present in a segment took the trend to −0.011. So PolEmo cannot corroborate the headline at all:
its median test review is 119 words and 3 of 684 are as short as the probe's sentences. The page
now says that in the section after the claim, and the prose branches on the result rather than
asserting it. Measured timings left the README and model card — they moved 6 500 → 3 900 rows/s
between runs with no code change.

**HerBERT round** (`feat/herbert-gpu-run`, PR #6, 209 tests). Fine-tuned locally on the user's
GTX 1050 — the venv's torch was a CPU-only build, and driver 457.49 (2020) takes cu118 only, so
that wheel had to be swapped in (revert with `pip install torch==2.13.0`). Result: **0.986
macro-F1 against the baseline's 0.944**, ten errors on the test split instead of forty-one,
McNemar 38 to 7 over 45 disagreements, p < 0.0001. 50 minutes of training against roughly three
seconds.

Two things worth carrying forward. The 4 GB card cannot hold the configured batch — measured,
16 and 8 both OOM at 256 tokens, 4 peaks at 2.37 GB — so the batch is split 4×4 and the
optimizer still steps on 16; `HERBERT_GRAD_ACCUM` exists for exactly this and the page prints
it. And the derived headline proved itself: it swung from the probe finding to the comparison
the moment the paired test existed, and the KPI row switched with it, without a hand edit.

The cascade is the result the page was built for: routing the least-confident **20%** to
HerBERT reaches 0.980 macro-F1 — 85% of what the transformer adds, for a fifth of the GPU
traffic. The quoted rate follows a stated rule rather than being picked for its number.
